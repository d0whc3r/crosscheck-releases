A second opinion.
Or two that challenge each other.

Use your installed Claude Code, Codex, OpenCode, or Antigravity CLI and its provider account.

AI findings can be wrong. PR context is sent to the provider behind your selected CLI. Crosscheck asks you to confirm before posting a review.

Standard review

One engine reads the PR or local folder.

Choose an engine, model, effort, and primary review skill, add your instructions, and run a review. Inspect the findings alongside the diff, or select “Dispute with adversary” to test a finished standard review with a second engine.

  1. Pull request or folder
  2. One engine
  3. Findings

Adversarial review

Two engines test the findings.

Two engines review independently, critique each other’s findings in fresh sessions, and answer the critiques. Assign a shared or per-engine primary review skill, and inspect confirmed, suspected, contested, and refuted findings in one report.

  1. Independent reviews
  2. Critique and rebuttal
  3. Report

Give each review the context it needs.

Preview the context

See what a review sends before it starts: the app rules, your instructions, the PR text, each file and hunk of the diff, and the first prompt. Leave out a file or a hunk you do not want to send.

Presets and native instructions

Save the mode, engines, primary review skill, extra instructions, skill groups, MCP servers, and preparation commands as a review preset. Crosscheck configures each CLI natively with your approved AGENTS.md or CLAUDE.md from the local clone.

Primary review skill, skills, and MCP

Choose a primary review skill per review or per engine, toggle skill groups as checkboxes, and attach MCP servers. Check and approve new or changed project sources before a review uses them.

Preparation commands and recovery

Configure ordered commands for worktree creation, updates, review start, or manual runs on demand from the Run command menu. Each command runs in its own terminal with CROSSCHECK_* variables. If one AI engine fails, keep the other’s findings and retry the failed engine.

Review local git folders

Register any git folder and review a branch comparison, a commit range, or individual staged and unstaged files without touching your working index. Run AI reviews, briefings, quizzes, and actions on a snapshot worktree, and copy comments as a fix prompt for a coding agent.

Detached windows and notifications

Run AI reviews concurrently across PRs and local folders, with desktop notifications when a run finishes or fails. Detach the review side panel or an AI findings report into its own window beside the diff.

A workspace for the whole review.

Move between repositories, related PRs, code, and conversations without losing your place.

Find the PR you are looking for

Explore pull requests across selected repositories with filters, or press ⌘K (Ctrl+K) to jump to a PR link, repository, local folder, disk path, or command.

Onboarding, repositories, and accounts

  • A first-run setup wizard configures your appearance, projects folder, AI engines, and default editor. Pin repositories, scan local folders for clones, bind a clone, or clone from a PR.
  • Switch between GitHub.com accounts. Each account keeps its own settings, bindings, drafts, history, and worktrees.

Know when a PR needs you

Save a search as a watch, follow concurrent AI reviews, and receive desktop notifications when a review finishes or fails.

Watches, queue, checks, and notifications

  • Start with the “Needs my review” watch, then see the matches of every watch in one queue, in lanes such as “To review”. Click a desktop notification to open the PR or local folder directly.
  • See the CI state of each PR, with the failed checks first. Keep a PR to revisit later with a private note.

Read code, Markdown, and HTML

Switch between split and unified diffs, expand surrounding code, preview rendered HTML with two-way comments, and read the PR description beside the changes.

Markdown, HTML preview, and review progress

  • Read Markdown as source, formatted before and after, or a combined view with word changes. Preview HTML files on their new or old side: comments on the rendered page map to source lines, and source notes show on the page.
  • Mark each file as reviewed as you go. Mark a commit as reviewed, then use “Since last review” to inspect only the changes that arrived later.

Understand the PR before you review

Generate a briefing, a structured review plan backed by diff evidence, and a comprehension quiz before you dive into the files.

Briefing updates, review plan, and quiz

  • The review plan extracts file roles, changed public declarations, and untested source files from the diff, then adds complexity, review order, and checks. After new commits, summarize only the forward changes since the last briefing while keeping the original.
  • Take a quiz of 6 to 8 questions on the diff, at an easy, medium, or hard level. Each answer links to the evidence in the files.

Follow the whole PR stack

Navigate native GitHub stacks in order, or switch to a stack view with files grouped by pull request and progress for each layer.

Actions across the stack

  • Select PRs to update their worktrees, mark them reviewed, run an AI review for each open PR, and preview the drafts of each one.
  • Merge the stack up to a chosen PR in one operation, with the merge queue and the rules of the trunk. The status survives a restart.

Ask about the code in front of you

Chat about a PR or local folder, or select lines and ask a question of one or several AI engines, with the answers side by side.

From questions to clearer comments

  • Ask AI to explain selected code, check edge cases, draft an inline comment, or help write a reply to a review thread. AI actions reuse the approved instructions, skills, and MCP servers of your last review.
  • Get suggested follow-up questions, read a long answer in a concise view, and refine a comment or the review draft through chat.

Keep your tools close

Open a PR worktree or local folder in your editor, file manager, or shell. Stack worktrees above the integrated terminal and detach the review side panel into its own window.

Worktrees, local folders, and workspace controls

  • Register any local git folder to review a branch comparison, a commit range, or individual staged and unstaged files, even while signed out of GitHub. Copy local comments and patches as a fix prompt for a coding agent.
  • Update outdated worktrees, inspect their disk use by repository, and remove unused worktrees or old AI run folders. Choose one of eight themes, an accent color, and a text size, or export your configuration to another computer.

Return to the review with its history

Reopen posted reviews, AI chats, briefings, review plans, and answers from the History view. Conversations record the commit the AI read.

History, cleanup, and troubleshooting

  • Keep follow-up questions in the conversation and see when an answer refers to an older commit. Clear local review data for a PR, clear individual entries, or confirm before reopening a merged or closed PR.
  • Check installed tools and connections in one place. Enable debug mode for a live log with filters when you need to investigate a failure.

Your comments.
Your decision on GitHub.

Write a manual review, use AI findings, or combine both. Posting a review does not require an AI run.

“Mark as reviewed” saves your place locally. It does not submit a review or approve the PR on GitHub.

Write inline comments and replies beside existing GitHub threads. Resolve or reopen threads as you review. Local drafts and unsent review text survive an app restart.

See your pending GitHub comments in the diff, including ones started on the web. Save selected drafts with “Start a review” or add to your existing pending review.

Check the posting account, select comments, and edit the exact text in the preview. Submit with Comment, Approve, or Request changes, subject to your GitHub permissions. Open the AI findings in a separate window beside the diff.
