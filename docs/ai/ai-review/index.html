AI review

An AI review reads the PR and returns findings that you can turn into comments. A standard review uses one engine. An adversarial review uses two engines that review on their own and then try to refute each other.

Before you start, set up an AI CLI.

Choose a mode

Section titled “Choose a mode”
Mode What happens
Standard One engine reviews the PR and returns findings
Adversarial Two engines review on their own. Each engine then tries to refute the findings of the other in a fresh session, and each author answers the refutations of its own findings once. The report sorts the findings into confirmed, suspected, contested, and refuted

Run a review

Section titled “Run a review”
  1. Open the “AI review” tab of the review. Its “Run” tab holds the form.
  2. Optional: choose a “Preset” to fill the form.
  3. Optional: choose a “Review skill”. In adversarial mode, choose “Same for both” or “Per engine”.
  4. Open “Review settings”:
    • Choose the “Mode”: “Standard” or “Adversarial”.
    • For each engine, choose the “Agent” and the “Model”. When the model has effort levels, also choose the “Effort”. In adversarial mode, choose two different CLIs, models, or efforts.
    • Choose the skills, the “Skill groups”, and the “MCP servers”. See Skills, MCP servers, and presets.
    • Add “Extra instructions”, if you want. “Improve instructions” can clarify them, make them concise, or turn them into a checklist.
  5. Optional: select “Preview context…” to check what the review sends. See Context preview.
  6. Select “Start review”.

The model list shows only the models that the CLI offers. Type in “Search models…” to filter it, and star a model to keep it in “Favorites”. The effort list shows only the efforts of the chosen model.

When the repository has preparation commands that run before a review, the app asks “Run the preparation commands?”. Choose “Run commands and start” or “Start without commands”.

When Claude Code does not trust the run folder yet, the form says so. Answer “Yes, I trust this folder” in the terminal, and then start.

Follow the run

Section titled “Follow the run”

The Run tab shows the stage, such as “Step 4 of 5 · Rebuttal”, and the activity of each engine.

Mode Stages
Standard Preparing, Reviewing
Adversarial Preparing, Reviewing, Critique, Rebuttal, Consensus
  • After three minutes with no activity, the run shows a notice with “Open terminal”, “Retry”, and “Stop”. The engine can wait for an answer in its terminal.
  • “Stop” asks you to confirm. The findings of a stopped run are lost.
  • A run continues while the app is closed, and the app resumes it at the next start.

You can run AI reviews on several PRs and local folders at the same time. When a run finishes, fails, or stalls, Crosscheck sends a desktop notification that opens the AI review. Set these notifications in Settings > Notifications.

Read the findings

Section titled “Read the findings”

Open the “Findings” tab, or select “View N findings” at the end of the run.

  • In a standard review, the findings are in the “Comments” list.
  • In an adversarial review, the findings are in the groups “Confirmed”, “Suspected”, “Contested”, and “Refuted”. Select a finding to read its detail. Use “Previous” and “Next”, or the Up and Down keys, to move between findings.
  • A run with no findings shows “Review done: no findings”.

In an adversarial review, a strip on top counts the findings of each group.

When the PR has new commits, the findings of the older commit are read-only. Select “Rerun on the new commit” to review the new head.

Act on the findings

Section titled “Act on the findings”
  • “Add as comment” opens a dialog where you edit the comment. The AI can “Merge into one message”, “Condense”, “Expand with the reason”, or “Suggest a fix”. Select “Add to review” to make it a draft.
  • “Open in the diff” shows the finding on its line.
  • “Reply in the thread” answers the GitHub thread of the finding.

To post the findings:

  • In a standard review, select “Post review…”.
  • In an adversarial review, check “Include in Post selected” on each confirmed finding, then select the post button. It shows “Post selected”, or counts what you checked, such as “Post 2 findings + 1 draft…”. Only a confirmed finding can go into the post.

For a local folder, the buttons add the findings as local comments instead. See Post to GitHub.

Dispute a standard review

Section titled “Dispute a standard review”

Select “Dispute with adversary” on a finished standard review. Crosscheck starts an adversarial review with the same configuration and a second engine.

Open the findings in a window

Section titled “Open the findings in a window”

Select “Open in a window” in the Findings tab. The result window shows the findings of the run beside the diff.

  • Select “Add to review” on a finding to make it a draft. Edit the draft, or select “Remove from the review”.
  • The main window holds the drafts, so each change shows in both windows.
  • When you change the same drafts in the main window first, the result window says that its last change was not saved.
  • “Show in main window” scrolls the main window to the finding in the diff.
  • “Reattach” brings the findings back to the main window. You post the review in the main window.

The result window closes with the main window and when you switch account.

When an engine fails

Section titled “When an engine fails”

In an adversarial review, the report keeps the findings of the engine that worked. “Retry” asks only the engine that failed. “Retry with” another CLI runs the failed side on that CLI.

Repeat a review

Section titled “Repeat a review”

Each run keeps its configuration: the mode, the engines, the preset, the review skill, the other skills, the MCP servers, the extra instructions, the preparation choice, and the context.

  • The form keeps these values after the run ends, also when you switch to another tab.
  • “Configuration of the last run” shows them under the run status.
  • “Start from this configuration” fills the form with them again.
  • “Previous reviews” opens an earlier run of the PR.
  • The History view lists every review run of a PR with its configuration. A run from an older version shows “Not recorded” for the values that it did not keep.

To run AI reviews on many PRs at once, see Batches.

Caution

AI findings can be wrong. PR context goes to the provider behind the CLI that you choose. See Privacy and safety.
