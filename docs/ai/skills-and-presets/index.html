Skills, MCP servers, and presets

A review can use skills, MCP servers, instructions, and preparation commands. Save a set of choices as a preset, and set a default preset for each repository. A review uses a project skill or a project server only after you approve it.

Presets

Section titled “Presets”

A preset saves the mode, the engines, the review skill, the skill groups, the skills, the MCP servers, the instructions, and the preparation commands.

  1. Open Settings > AI review, and go to “Presets and skill groups”.
  2. Under “Review presets”, select “New preset”, and give it a name.
  3. Set its choices, and select “Save”.

To use a preset, choose it in “Preset” of the review form. To make it the default of a repository, set “Default AI preset” on the Repositories page.

Skills and skill groups

Section titled “Skills and skill groups”
  • A review skill leads the review. Choose it in “Review skill” of the review form or of a preset. In adversarial mode, choose “Same for both” or “Per engine”. With no choice, the review uses “Built-in review (default)”.
  • Other skills go in “Additional skills”. Set each one to “Enabled”, “Optional”, or “Off”. An optional skill applies only when it fits.
  • “Add a temporary skill…”, at the end of the skill list, adds a skill for one review only.
  • A skill group is a named set of skills and MCP servers. Create one under “Skill groups” in Settings > AI review with “New group”. The review form shows each group as a checkbox.
  • To add skills to the app library, select “Import skills…” in Settings > Agents and integrations. Type the source in “Import from”, such as owner/repo, and select “Import”.

MCP servers

Section titled “MCP servers”

Choose the MCP servers of a review in “MCP servers”. The models may call every tool of a chosen MCP server, also tools that write or send data.

Instructions

Section titled “Instructions”
  • “Extra instructions” add your text to the review prompt.
  • A repository can have its own default instructions. Write them in the review form and select “Save as default for this repo”, or set them on the Repositories page.
  • “Instructions from” chooses what a review uses when both the preset and the repository have instructions: “Preset”, “Repo”, or “Both”.

Crosscheck also reads AGENTS.md, or else CLAUDE.md, from the local clone, after your approval. It gives each CLI the instructions and skills in its own native form. The AI actions, the chat, the briefing, the review plan, and the quiz load the approved setup of the last review.

Project sources and approvals

Section titled “Project sources and approvals”

“Use the skills of this repository” adds these as optional choices:

  • the project skills of the local clone,
  • the skills of the plugins that its settings turn on,
  • its project MCP servers.

A project source, such as the instructions file, a skill, or a server, needs your approval before a review uses it. Select “Approve project sources” in the review form. When a project source changes after its approval, the review stops until you approve it again.

Preparation commands

Section titled “Preparation commands”

A preparation command is a shell line that runs in the worktree of a PR, such as an install or a build. Set the commands of a repository on the Repositories page. A preset can add more commands. For a local folder, the commands run in its snapshot worktree, never in your folder, and you approve each command once for the folder.

Each command has one or more triggers:

  • “Worktree created”
  • “Worktree updated”
  • “Before a review”
  • “Manual (Run command menu)”

Give a manual command a name, such as Lint. The review page then shows it in the “Run command” menu. With “Watched files”, the command runs only when those files changed since its last success.

To run the commands:

  1. Read the commands of the PR head.
  2. Select “Approve and run”. For a later run, select “Run”.
  3. Follow the output. “Stop” ends a command. “Retry” runs the failed commands again.

Each command runs in its own terminal. “Open terminal” opens it in the Worktrees and terminals view, while the command runs and after it ends. When a command asks a question, such as sudo for a password, answer it there.

Each command can read these environment variables: CROSSCHECK_WORKTREE, CROSSCHECK_CLONE, CROSSCHECK_REPO, CROSSCHECK_PR, CROSSCHECK_AUTHOR, CROSSCHECK_HEAD_SHA, CROSSCHECK_BASE_SHA, CROSSCHECK_BASE_REF, CROSSCHECK_BRANCH_SLUG, and CROSSCHECK_TRIGGER. Quote them in the line, such as cp "$CROSSCHECK_CLONE/.env" "$CROSSCHECK_WORKTREE".

Caution

A preparation command can run code of the PR, such as an install script. Approve it only for PRs that you trust.

See what the CLIs offer

Section titled “See what the CLIs offer”

Settings > Agents and integrations shows the resources that Crosscheck finds, in two views.

  • Resources lists the “Skills”, “Plugins”, and “MCP servers”, grouped by where they come from. It has search, counts, and the items that need approval. A plugin row shows how many skills it provides, and “Show its skills” filters the skill list. Select a row to see its path and origin.
  • Sources shows the resolved paths and file errors. Expand “Repository source overrides” to set a CLI root, a working folder inside the clone, or extra skill folders. Skills in extra folders need your approval.

Use “Show configuration for” to choose what the views read: your user configuration only, or also the local clone and the saved overrides of a repository. The second choice shows what a review of that repository can use.

  • “Refresh” reads changes made outside Crosscheck.
  • Crosscheck does not edit the files of the external CLIs.
  • Detection does not check a sign-in or choose a resource for a review.
