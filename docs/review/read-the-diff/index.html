Read the diff

A review has four tabs. The Changes tab shows the diff of the PR next to a file tree and a side panel. Choose the layout, read Markdown and HTML as source or as a page, and mark each file as reviewed.

The tabs of a review

Section titled “The tabs of a review”
Tab What it shows
Overview The review stats, the AI briefing, the review plan, the quiz, and the checks. See Briefing, review plan, and quiz
Changes The diff, the file tree, and the side panel. The tab counts the reviewed files
AI review The AI review form, its progress, and its findings. See AI review
Stack The other PRs of a native GitHub stack. See Stacks

The side panel of the Changes tab has the “Comments”, “Description”, and “Chat” tabs.

Change the layout

Section titled “Change the layout”

The diff toolbar holds these choices:

  • “Full” or “Since last review” sets the scope.
  • “One file” or “All files” shows one file, or every file in one list.
  • “Split” or “Unified” sets the layout.

You can also:

  • Expand the code around a hunk to read more context.
  • Drag the separators to resize the sidebar, the file tree, and the side panel.
  • Select “Side panel” to hide or show the side panel.
  • Select “Open in a window” to move the side panel to its own window. It follows the PR or the local folder of the main window. Select “Reattach” to bring it back.
  • Hide the file tree with its button, and show it again from the file header.

Move with the keyboard

Section titled “Move with the keyboard”
Key Action
J and K Go to the next file and the previous file
C Pick a line to comment on
Command+Enter on macOS, Ctrl+Enter on Linux Add the comment to the review
Esc Close the comment composer
Shift+J and Shift+K Go to the PR above and the PR below in a stack

In the file tree, use the arrow keys, Home, End, Enter, and Space.

Read Markdown

Section titled “Read Markdown”

Choose the view of a Markdown file in its header:

  • “Raw” shows the source diff.
  • “Formatted” shows the page before and after the change.
  • “Combined” shows one page with the word changes.

The Combined view marks each block as added, deleted, or changed, and shows the changed words inside a block.

To comment, hover a changed block and select its button to show the source lines. A Mermaid block shows as a diagram. Use “Zoom in”, “Zoom out”, and “Fit to width”, or select “Open expanded preview”. In the preview, “Open in a window” opens the diagram in its own window.

Read HTML

Section titled “Read HTML”

Choose the view of an HTML file in its header:

  • “Raw” shows the source diff.
  • “Rendered” shows the new page.
  • “Before” shows the old page.

To comment on the page:

  1. Select “Select element”. The toolbar shows “Selecting…”.
  2. Select an element on the page. The comment composer opens on its source lines.
  3. Write the comment, and select “Add to review”.

Notes on source lines show as pins on the page. Select a pin to read its notes. Press Esc to stop the selection.

The page runs no scripts until you turn on “Run page scripts”. The page cannot reach the network. “Open in browser” opens the page in your browser, and its “Select element” button sends the lines back to Crosscheck.

Read the PR description

Section titled “Read the PR description”

Open the “Description” tab of the side panel.

Crosscheck renders the description as Markdown with the same safety rules as AI text:

  • It shows raw HTML as text.
  • It opens only GitHub links.
  • It loads images only from GitHub.

Select the refresh button, “Refresh the description”, to load an edited description. The tab does not change the worktree, the selected file, or your drafts, and it starts no AI work.

Track the files you reviewed

Section titled “Track the files you reviewed”

Select “Mark file reviewed” in the header of each file that you finish. The file tree shows a check on each reviewed file, and the diff toolbar counts them, such as “3 of 6 files reviewed”.

  • The file tree has “Mark all as reviewed” and “Unmark all”.
  • For a PR, a file mark also marks the file as viewed on GitHub.
  • A mark applies to the full change of the file in the PR. When new commits change the file, the file needs review again.

Review only the new commits

Section titled “Review only the new commits”
  1. Select “Mark as reviewed” in the tab row of the Changes tab. It saves the current head as your place, and it posts nothing to GitHub.
  2. After new commits, select “Since last review” to see only the later changes.
  3. Select “Full” to return to the complete diff.

When the PR history changed, for example after a force push, the review shows the full diff and says so.

Note

A deleted line in “Since last review” cannot take a comment. Switch to “Full”, so that the line matches the review positions of GitHub.

Update the worktree

Section titled “Update the worktree”

When GitHub has new commits that the worktree lacks, the “Worktree out of date” banner shows. Select “Update worktree”. When the worktree has local changes, the app keeps the old checkout. Select “Discard local changes” to drop them.

Limits

Section titled “Limits”
  • A file with more than 3,000 changed lines starts folded. Select “Load diff” to show it.
  • Crosscheck does not show a diff larger than 64 MiB. Review that PR on GitHub, or open its worktree in an editor.
